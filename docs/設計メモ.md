# 我が家のレシピアプリ 設計メモ

壁打ちで決めた内容のまとめ（2026-11-26）。

## 使う人・使う場面

- 主に自分。夫も見るかもしれない → 2人で同じレシピを共有する
- スマホ（Android）で見る。作るときは Nest Hub に「画面をキャスト」で映す
- 料理は**週末だけ**。土曜・日曜の夕食2回分 ＋ 子ども用の冷凍OK副菜（2品くらい）を休日にまとめて作る

## 困りごと → アプリでの解決

| 困りごと | 解決 |
|---|---|
| 調味料を変えたら紙に書く→MDに起こす→印刷、が面倒 | アプリ内でその場で編集。前の分量は履歴で見られる（最新版に上書き＋履歴でOK） |
| 作った写真を載せたい | レシピに写真を追加 |
| **食材を余らせる（一番大変）** | 冷蔵庫の在庫登録は**しない**（面倒なので）。週末プランを立てる時点で「人参1/2本が余ります」と知らせ、余りを使うレシピを提案する |
| 献立を考えるのが大変 | 週末プラン（土日夕食2回＋冷凍副菜） |
| 雑誌・テレビ・思いつきのレシピを追加したい | 写真や音声を Claude アプリで整形 → アプリに貼り付けて取り込む（APIは使わない＝費用ゼロの方式） |
| いつか本にして子どもに渡したい | 写真付きレシピ本のPDF書き出し |

## 栄養素（2026-11-26 追加）

- 全レシピに1人分の栄養素を表示（カロミルの「Myメニュー」と同じ7項目：カロリー・たんぱく質・脂質・炭水化物・糖質・食物繊維・塩分）
- 値はClaudeが材料と日本食品標準成分表から見積もった目安。Markdownの「## 栄養（1人分）」に書く。編集画面で直せる
- 分量だけ変えて保存したら「分量が変わったので栄養素は目安です」と表示（栄養素を書き換えると消える）
- 何人分は数字1つで書く（「2〜3人分」はやめる。幅があるときは多いほうで割る）
- 新しいレシピは、Claudeアプリ用の依頼文で栄養素も一緒に計算してもらう
- 使い道：カロミルに記録するため。ゆくゆくは自作の記録アプリに乗り換えたい。記録アプリへ移しやすくする機能はまだ作らない

## 手抜き版とちゃんと版（2026-11-26 追加）

- 普段は手抜き（下ごしらえを省く・カット野菜・ホットクック）、時々ちゃんと作る、の2パターンがある
- 1つのレシピに両方を持たせ、レシピ画面の上で［手抜き 10分］［ちゃんと 40分］と切り替える。調理モードでも切り替えられる
- 今までのレシピ＝手抜き版。ちゃんと版はClaudeが下書きした（要確認）
- Markdownでは「## 材料」「## 手順」が手抜き版、「## ちゃんと版：材料」「## ちゃんと版：手順」などがちゃんと版。時間は先頭の「時間:」「ちゃんと版の時間:」
- 所要時間＝食べられるまでの時間（ホットクック等が動いている時間も含む。漬け込み・一晩置く時間は除く）
- 手間＝そのうち手を動かす時間。先頭の「手間:」「ちゃんと版の手間:」。全体との差が5分以内なら表示しない（表示をシンプルに保つため）
- 栄養素は手抜き版の材料から計算したもの
- 今後：週末プランで「今週はこれを手抜きで」と選ぶと、買い物リストがカット野菜などになる（食材の余りを減らす）

## 作る予定と買い物リスト（2026-11-26 追加）

- 「土曜の夕食」などの枠は作らない。作りたいものを好きなだけ選ぶ（一覧の「＋」、レシピ画面の「作る予定に入れる」）
- 料理ごとに手抜き／ちゃんとを選べる。選んだ版の材料で計算する
- 人数はレシピのまま（いつも2人分。4人分は2日に分けて食べる）
- 余りの計算：よくある売り方（人参1本、ピーマン5個入り袋、なす3本入り袋など）で買ったときに余る量を出す。30g未満の余りは気にしない
  - 売り方の表は app/src/lib/shopping.ts の PRODUCTS。お店に合わせて変えてよい
  - 肉・魚はパックの量がまちまちなので余りは出さず、合計のグラムだけ
- 余る食材を使えるレシピを提案（冷凍OKの副菜を優先）。押すと作る予定に足せる
- 買い物リストは売り場ごと。チェックしながら買える。調味料・にんにく等は「家にあるか確認」に名前だけ
- 作る予定はスマホの中に保存。共有はスクショで送る

## 段階計画

| 段階 | 内容 |
|---|---|
| 第1段階 | 43品の取り込み、一覧・検索・詳細、編集と履歴、写真、共有、調理モード（大きい文字・画面が消えない） |
| 第2段階 | 作る予定（週末プラン）、買い物リスト、余り食材のお知らせと使い切り提案 ← 2026-11-26 できた |
| 第3段階 | 写真・音声からの取り込み（Claudeアプリ用の依頼文コピー → 結果を貼り付け） |
| 第4段階 | レシピ本PDFの書き出し |

## 技術

- `app/`：Vite + React + TypeScript のWebアプリ（ホーム画面に追加できるPWA）
- **GitHubだけで完結**（登録するサービスを増やしたくないため。レシピと料理の写真なので公開リポジトリでOK）
  - 正本はリポジトリのMarkdownファイル。アプリでの保存はGitHub APIでコミット（変更メモ＝コミットメッセージ、履歴＝コミット履歴）
  - 写真は `写真/` に保存し、Markdownの `写真:` に書く
  - 公開は GitHub Pages。main 更新のたびに Actions で作り直す
  - 編集する端末には fine-grained personal access token（このリポジトリの Contents 読み書きだけ）を登録。見るだけなら不要
- 検討してやめた案：Firebase（Googleのサービス）。登録するサービスを増やさないことを優先した
