# レシピアプリ 設計メモ

このアプリの考え方と、主な設計の決めごと。

## ねらい

| 困りごと | アプリでの解決 |
|---|---|
| 調味料を変えるたびに、紙に書き足して清書し直すのが面倒 | アプリ内でその場で編集。前の分量は変更の履歴で見られる |
| 作った料理の写真を残したい | レシピに写真を追加 |
| **食材を余らせる** | 冷蔵庫の在庫登録は**しない**（続かないので）。作るものを選んだ時点で「人参1/2本が余ります」と知らせ、余りを使うレシピを提案する |
| 献立を考えるのが大変 | 作りたいものを選ぶと、買い物リストまで出る |
| 雑誌・テレビ・思いつきのレシピを追加したい | 写真や音声を Claude アプリで整形 → アプリに貼り付けて取り込む（APIは使わない＝費用ゼロの方式） |
| いつか本の形で残したい | 写真付きレシピ本のPDF書き出し（予定） |

## 栄養素

- 全レシピに1人分の栄養素を表示（食事記録アプリでよく使う7項目：カロリー・たんぱく質・脂質・炭水化物・糖質・食物繊維・塩分）
- 値は材料と日本食品標準成分表から見積もった目安。Markdownの「## 栄養（1人分）」に書く。編集画面で直せる
- 分量だけ変えて保存したら「分量が変わったので栄養素は目安です」と表示（栄養素を書き換えると消える）
- 何人分は数字1つで書く（「2〜3人分」のような幅は書かない。幅があるときは多いほうで割る）
- 新しいレシピは、Claudeアプリ用の依頼文で栄養素も一緒に計算してもらう

## 手抜き版とちゃんと版

- 下ごしらえを省いたり調理家電に任せたりする「手抜き」と、時間をかける「ちゃんと」の2通りの作り方がある
- 1つのレシピに両方を持たせ、レシピ画面の上で［手抜き 10分］［ちゃんと 40分］と切り替える。調理モードでも切り替えられる
- Markdownでは「## 材料」「## 手順」が手抜き版、「## ちゃんと版：材料」「## ちゃんと版：手順」などがちゃんと版。時間は先頭の「時間:」「ちゃんと版の時間:」
- 所要時間＝食べられるまでの時間（調理家電が動いている時間も含む。漬け込み・一晩置く時間は除く）
- 手間＝そのうち手を動かす時間。先頭の「手間:」「ちゃんと版の手間:」。全体との差が5分以内なら表示しない（表示をシンプルに保つため）
- 栄養素は手抜き版の材料から計算したもの

## 作る予定と買い物リスト

- 「〇曜の夕食」のような枠は作らない。作りたいものを好きなだけ選ぶ（一覧の「＋」、レシピ画面の「作る予定に入れる」）
- 料理ごとに手抜き／ちゃんとを選べる。選んだ版の材料で計算する
- 人数はレシピのまま（増やす・減らす計算はしない）
- 余りの計算：よくある売り方（人参1本、ピーマン5個入り袋、なす3本入り袋など）で買ったときに余る量を出す。30g未満の余りは気にしない
  - 売り方の表は app/src/lib/shopping.ts の PRODUCTS。お店に合わせて変えてよい
  - 肉・魚はパックの量がまちまちなので余りは出さず、合計のグラムだけ
- 余る食材を使えるレシピを提案（冷凍OKの副菜を優先）。押すと作る予定に足せる
  - 足すと別の食材が余って「余りが余りを呼ぶ」ことがないよう、足したあとに全体の余りが減るものだけを出す
- 買い物リストは売り場ごと。チェックしながら買える。調味料・にんにく等は「家にあるか確認」に名前だけ
- 作る予定は一緒に使う人と共有。誰かが提案し、ほかの人が自分の端末で直し、買い物もそのリストを見ながらできる。「誰が追加」「誰が買った」「最終更新：〇〇・3分前」を表示。名前はGitHubのユーザー名
  - 保存先は GitHub の plan ブランチの plan.json（レシピの履歴とは別。スマホ版の作り直しも起きない）
  - 操作（足す・外す・切り替え・チェック）を最新の内容に1つずつ重ねて保存するので、同時に触っても消えない。開いている間は20秒ごとに最新にする
  - 一緒に使う人は Collaborator に招待。鍵は classic token の public_repo
  - 見るだけの端末は想定しない（作る予定は鍵を登録した端末で使う）

## 段階計画

| 段階 | 内容 |
|---|---|
| 第1段階 | レシピの取り込み、一覧・検索・詳細、編集と履歴、写真、調理モード（大きい文字・画面が消えない） ← できた |
| 第2段階 | 作る予定、買い物リスト、余り食材のお知らせと使い切り提案、共有 ← できた |
| 第3段階 | 写真・音声からの取り込み（Claudeアプリ用の依頼文コピー → 結果を貼り付け） ← できた |
| 第4段階 | レシピ本PDFの書き出し |

## 技術

- `app/`：Vite + React + TypeScript のWebアプリ（ホーム画面に追加できるPWA）
- **GitHubだけで完結**（使うサービスを増やさないため）
  - 正本はリポジトリのMarkdownファイル。アプリでの保存はGitHub APIでコミット（変更メモ＝コミットメッセージ、履歴＝コミット履歴）
  - 写真は `写真/` に保存し、Markdownの `写真:` に書く
  - 公開は GitHub Pages。main 更新のたびに Actions で作り直す
  - 編集する端末には鍵（personal access token）を登録。見るだけなら不要
  - コミットにはGitHubの匿名アドレスを使い、本当のメールアドレスを残さない
  - 保存先のリポジトリはビルド時に自動で決まる（コピーした人は自分のリポジトリに保存される）
